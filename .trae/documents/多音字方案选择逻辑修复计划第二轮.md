# 多音字方案选择逻辑修复计划（第二轮）

## 一、问题分析

### 问题1：切换面板后勾选被清空

**现状**：选择"无"引擎时，勾选方案后切换面板再回来，勾选状态被清空。

**原因**：
1. 每次调用`refresh多音字替换Ui()`时，如果是"无"引擎，会调用`loadSelectedSchemes()`从配置重新加载
2. 用户勾选后没有实时保存到配置，只在点击"开始替换"按钮时才保存
3. 切换面板时会触发`refresh多音字替换Ui()`，导致从配置重新加载，覆盖了内存中的勾选状态

**用户期望**：
- 勾选状态应该在内存中保留
- 只在软件启动时从配置加载一次
- 更改后实时写入配置

### 问题2：点击勾选需要多次才能成功

**现状**：如果某个方案是当前选中项（高亮显示），再次点击勾选时，往往需要点数次才能勾选上。

**原因**：
1. Click事件中手动切换勾选状态：`SetItemChecked(index, !currentState)`
2. CheckedListBox的行为：点击某项会先选中该项（设置SelectedIndex），然后触发Click事件
3. 如果点击的是已选中项，Click事件仍然触发，但此时`SelectedIndex`已经是该项
4. 问题在于Click事件和ItemCheck事件的交互：
   - Click事件中手动调用`SetItemChecked`会触发ItemCheck事件
   - 但ItemCheck事件在勾选状态改变**之前**触发
   - 导致状态判断混乱

**解决方案**：使用`ItemCheck`事件替代`Click`事件来处理勾选逻辑，或者移除Click事件中的手动切换逻辑。

## 二、修复方案

### 2.1 问题1修复：勾选状态内存管理

**修改逻辑**：
1. 新增私有字段`_userSelectedSchemes`保存用户勾选的方案名称（内存缓存）
2. 只在初始化时从配置加载一次
3. 用户勾选/取消勾选时，实时更新内存缓存并写入配置
4. `refresh多音字替换Ui()`中从内存缓存加载勾选状态，而不是从配置文件

```csharp
/// <summary>
/// 用户选中的方案名称列表（内存缓存）。
/// </summary>
private HashSet<string> _userSelectedSchemes = new HashSet<string>();

/// <summary>
/// 标记是否已从配置加载过方案选择。
/// </summary>
private bool _hasLoadedSchemesFromConfig = false;
```

**修改`loadSelectedSchemes()`方法**：
```csharp
private void loadSelectedSchemes()
{
    // 只在首次加载时从配置读取
    if (!_hasLoadedSchemesFromConfig)
    {
        var savedSchemes = Setting.GetValue(this.clb_选择多音字方案.Name, string.Empty);
        var schemeArray = savedSchemes.Split(new[] { ',' }, StringSplitOptions.RemoveEmptyEntries);
        _userSelectedSchemes = new HashSet<string>(schemeArray);
        _hasLoadedSchemesFromConfig = true;
    }

    // 从内存缓存设置勾选状态
    for (int i = 0; i < this.clb_选择多音字方案.Items.Count; i++)
    {
        var itemName = this.clb_选择多音字方案.Items[i].ToString();
        this.clb_选择多音字方案.SetItemChecked(i, _userSelectedSchemes.Contains(itemName));
    }
}
```

**修改`saveSelectedSchemes()`方法**：
```csharp
private void saveSelectedSchemes()
{
    if (_isEngineSetSchemes) return;

    // 更新内存缓存
    _userSelectedSchemes.Clear();
    foreach (var item in this.clb_选择多音字方案.CheckedItems)
    {
        _userSelectedSchemes.Add(item.ToString());
    }

    // 写入配置
    Setting.SetValue(this.clb_选择多音字方案.Name, string.Join(",", _userSelectedSchemes));
}
```

**修改`ItemCheck`事件**：实时保存勾选状态
```csharp
private void clb_选择多音字方案_ItemCheck(object sender, ItemCheckEventArgs e)
{
    // 延迟执行，等待勾选状态更新完成
    this.BeginInvoke(new Action(() =>
    {
        // 更新内存缓存并保存到配置
        if (!_isEngineSetSchemes)
        {
            _userSelectedSchemes.Clear();
            foreach (var item in this.clb_选择多音字方案.CheckedItems)
            {
                _userSelectedSchemes.Add(item.ToString());
            }
            Setting.SetValue(this.clb_选择多音字方案.Name, string.Join(",", _userSelectedSchemes));
        }

        // 刷新按钮状态
        this.bt_开始替换最终文本中的多音字.Enabled =
            !_do多音字替换Working &&
            this.clb_选择多音字方案.CheckedItems.Count > 0 &&
            this.tb_最终文本.Text.Length > 0 &&
            _savedPolyphonicItemArray.Length > 0;
    }));
}
```

### 2.2 问题2修复：点击勾选冲突

**修改逻辑**：
移除`Click`事件中的手动切换逻辑，改为仅使用`ItemCheck`事件。

**原因**：
- CheckedListBox默认行为：点击复选框区域会自动切换勾选状态
- Click事件中的手动切换会导致双重切换（先自动切换，再手动切换回来）

**修改`Click`事件**：
```csharp
private void clb_选择多音字方案_Click(object sender, EventArgs e)
{
    // 不再需要手动切换勾选状态
    // CheckedListBox点击复选框区域会自动切换
    // 此事件保留用于其他可能的用途
}
```

**或者完全移除Click事件处理**，因为CheckedListBox默认支持点击切换勾选状态。
